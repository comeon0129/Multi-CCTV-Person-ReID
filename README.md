# 📷 실시간 다중 CCTV 객체 추적(Person Re-ID) 시스템

> 대규모 영상 트래픽 상황에서 백엔드 시스템의 병목 현상을 진단하고, 아키텍처 레벨에서 성능을 최적화한 프로젝트입니다. (진행 기간: 2026.03 ~ 2026.11)

## 🛠 주요 기술 스택
- **Backend**: Java, Spring Boot, Spring Data JPA
- **Database & Cache**: PostgreSQL, pgvector, Redis
- **Infra & Message Queue**: AWS (EC2, RDS), Docker, RabbitMQ
- **Test**: JMeter

## 🚀 설계 목표 및 트래픽 가정
- **예상 트래픽:** 100대의 CCTV에서 초당 20프레임 지속 유입
- **데이터 규모:** 50만 건 이상의 인물 특징 벡터(Feature Vector)가 DB에 누적된 상황 가정
- **목표:** 영상 데이터 폭증 시에도 에러율 0% 유지 및 1초(1000ms) 이내 응답 완료

## 🔥 핵심 트러블슈팅 및 3단계 성능 최적화

### 1단계: AI 추론 지연에 따른 백엔드 메모리 부하 방어 (비동기 큐 도입)
- **문제:** AI 추론(프레임당 150ms) 지연 시 백엔드 서버 메모리 고갈 및 요청 유실 위험
- **해결:** Spring Boot와 AI 서버 간 통신을 **RabbitMQ 기반 비동기 방식**으로 분리, 메시지를 프레임 단위로 그룹화(Batch)하여 네트워크 왕복 비용 최소화

### 2단계: 50만 건 벡터 데이터 풀 스캔 지연 개선 (차원 축소 및 Vector DB)
- **문제:** RDBMS 문자열 풀 스캔 시 검색 속도 급감 (Isolation Test로 DB 병목 입증)
- **해결:** AI 파트와 협력해 벡터를 2048차원에서 128차원으로 압축(PCA), **PostgreSQL(pgvector) 및 HNSW 인덱스** 적용 -> 검색 속도 **9ms**로 단축

### 3단계: 대용량 트래픽에 의한 DB I/O 병목 돌파 (인메모리 캐싱)
- **문제:** JMeter 100대 가상 트래픽 부하 테스트 시 DB CPU 264% 도달, 19.8% TimeOut 발생
- **해결:** 구역별 최근 식별 인물을 **Redis Hash 구조로 캐싱**하여 DB 접근 원천 차단. (Jackson 역직렬화 에러를 문자열 파싱으로 우회)
- **성과:** DB CPU 사용률 **0%대** 진입, **TPS 약 6배 향상** (802 → 4922), 전체 응답 속도 **5배 단축** (860ms → 165ms)
